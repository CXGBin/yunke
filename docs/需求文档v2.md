# 第一章 项目总览

## 1.1 项目概述

**云科智教**是一套面向教育培训机构的课程全生命周期管理平台，覆盖课程发布、选课、排课、签到、请假、评价、课程费结算、通知推送、数据分析、机构年费套餐等核心业务。系统包含：

- **机构端小程序**（机构管理员）：机构管理、教师管理、学生管理、课程管理、排课调度、签到管理、评价管理、数据报表、结算管理、套餐购买续费
- **教师端小程序**（教师）：查看排课、课堂签到、查看评价、查看课时费收入、查看教学数据
- **学生/家长端小程序**（学生/家长）：课程浏览、选课、课表查看、签到、请假、课程评价、查看个人学习报告
- **平台管理端PC**（平台管理员）：机构管理、套餐管理、平台数据监控、系统配置

> ⚠️ **变更说明**：原v2.0中教师用PC端+小程序、机构管理员用小程序的设计已调整。现统一为：机构端/教师端/学生家长端全部为小程序，仅平台管理端为PC端。

### 1.2.5 机构与校区关系

- **机构（Organization）**：最高租户单元，一个机构就是一个独立的教育实体（如"阳光少儿英语"）
- **校区（Campus）**：机构下的物理分支，用于排课、签到等场景（如"阳光少儿英语-海淀校区"）
- 一个机构包含多个校区（至少1个默认校区），校区数量受套餐上限限制（变更5）
- 所有业务数据（课程、排课、签到）挂载到**校区**维度
- ~~教室管理已删除，排课直接关联校区（变更4）~~
- 教师和学生归属到具体校区（通过多机构绑定可归属多个机构/校区）
- 数据隔离：机构管理员可查看本机构所有校区数据；教师/学生可查看所有绑定机构/校区的数据（变更8）

## 1.4 全局设计

### 1.4.1 多租户架构（共享库 + TenantId）

> **核心决策**：采用共享数据库 + TenantId 字段方案（不使用数据库隔离），方便平台方跨租户汇总统计数据。

**架构说明**：
- 所有业务表均包含 `TenantId`（即机构ID）字段，数据通过 TenantId 隔离
- 一个机构（租户）对应一个 TenantId，机构下的校区通过 CampusId 进一步细分
- 平台管理员可跨 TenantId 查询，实现全平台汇总统计（课程数、学员数、营收等）
- 教师/学生可跨机构查看（根据UserOrgBinding合并所有绑定机构数据）

### 1.4.2 SqlSugar 多租户全局过滤器

在 ORM 层（SqlSugar）实现租户数据的自动过滤，避免业务代码手动处理：

```csharp
// JwtMiddleware 解析 Token → 注入 CurrentTenantId 到 HttpContext
// SqlSugar 拦截器自动追加 WHERE TenantId = @CurrentTenantId

// 配置方式（Program.cs / Startup）：
sqlSugar.AddFilterTable(new TableFilterItem<object>(t =>
    t.TenantId == CurrentTenantId));

// 平台管理员查询时，移除过滤器实现跨租户查询：
sqlSugar.RemoveFilterTable(typeof(Course));

// 教师/学生跨机构查询时，根据UserOrgBinding获取所有TenantId列表
// 临时修改过滤器为 IN (@tenantIds) 查询
```

**关键规则**：
1. 所有业务实体基类包含 `TenantId` 字段
2. 中间件从 JWT Token 提取 TenantId 注入请求上下文
3. SqlSugar 全局过滤器自动追加 `WHERE TenantId = @val`
4. 平台管理员跨租户查询时，通过标记显式移除过滤器
5. 教师/学生跨机构查询时，根据 UserOrgBinding 动态构建多租户过滤条件
6. 创建/更新操作自动填充 TenantId，无需业务层手动赋值
7. 平台管理员（TenantId = NULL）不受过滤器影响

### 1.4.3 多校区隔离

- 所有业务数据通过 `TenantId` + `CampusId` 字段隔离
- 机构管理员可查看本租户所有校区数据（过滤器仅按 TenantId）
- 平台管理员可跨租户查看（移除过滤器）
- 教师/学生/家长通过邀请绑定归属到机构和校区，可查看所有绑定机构/校区的数据（变更8）

### 1.4.4 主题切换（所有小程序端）

- 支持多套主题样式（如：蓝色科技风、绿色清新风、紫色优雅风）

### 2.3.3 升级折价算法（变更6，详细展开）

**算法定义**：

```
已使用月数 = Ceil((当前日期 - 订阅开始日期) / 30)
  注：使用的月份数向上取整（即用了3.5个月算作4个月已用）

未使用月数 = 总月数(12) - 已使用月数

老套餐月均价格 = 老套餐年费 / 12

折价金额 = 老套餐月均价格 × 未使用月数

升级应付金额 = 新套餐年费 - 折价金额
```

**数学公式**：

$$已使用月数 = \lceil \frac{当前日期 - 订阅开始日期}{30} \rceil$$

$$未使用月数 = 12 - 已使用月数$$

$$折价金额 = \frac{老套餐年费}{12} \times 未使用月数$$

$$升级应付金额 = 新套餐年费 - 折价金额$$

**边界条件**：
- 若 `升级应付金额 ≤ 0`，则应付金额为 0（直接免费升级）
- 若 `已使用月数 ≥ 12`，则折价金额为 0（已用完一年，无折价）
- 若 `未使用月数 < 0`，则未使用月数按 0 计算

**示例计算**：

**示例1**：机构购买 Pro 套餐（年费1200元），使用3.5个月后升级为 Ultra 套餐（年费3600元）：

```
已使用月数 = Ceil(3.5) = 4个月
未使用月数 = 12 - 4 = 8个月
老套餐月均价格 = 1200 / 12 = 100元/月
折价金额 = 100 × 8 = 800元
升级应付金额 = 3600 - 800 = 2800元
```

**示例2**：机构购买 Plus 套餐（年费600元），使用5个月后升级为 Pro 套餐（年费1200元）：

```
已使用月数 = 5个月
未使用月数 = 12 - 5 = 7个月
老套餐月均价格 = 600 / 12 = 50元/月
折价金额 = 50 × 7 = 350元
升级应付金额 = 1200 - 350 = 850元
```

**示例3**：机构购买 Pro 套餐（年费1200元），使用11个月后升级为 Ultimate 套餐（年费6000元）：

```
已使用月数 = 11个月
未使用月数 = 12 - 11 = 1个月
老套餐月均价格 = 1200 / 12 = 100元/月
折价金额 = 100 × 1 = 100元
升级应付金额 = 6000 - 100 = 5900元
```

**示例4**：机构购买 Pro 套餐（年费1200元），使用0.5个月后升级为 Ultimate 套餐（年费6000元）：

```
已使用月数 = Ceil(0.5) = 1个月
未使用月数 = 12 - 1 = 11个月
老套餐月均价格 = 1200 / 12 = 100元/月
折价金额 = 100 × 11 = 1100元
升级应付金额 = 6000 - 1100 = 4900元
```

# 第三章 系统管理模块

## 3.1 模块概述

系统管理模块是平台的基础设施模块，包含机构管理、校区管理、用户管理、角色权限管理、主题配置、多机构绑定、邀请链接等功能。本模块是其他所有业务模块的前置依赖。

**本章重点变更**：
- 用户与机构关系从"单归属"改为"多对多绑定"

## 3.3 业务流程

### 3.3.1 机构开通流程

```
平台管理员在后台创建机构
      │
      ▼
填写机构信息（名称/Logo/联系人/联系电话/地址）
      │
      ▼
自动创建：
  ├─ 机构记录（Organization表）
  ├─ 默认校区（Campus表，名称=机构名称+"默认校区"）
  ├─ 机构管理员账号（SysUser表，Role=2）
  └─ 机构基础配置（OrgConfig表）
      │
      ▼
平台管理员通知机构管理员初始账号密码
      │
      ▼
机构管理员首次打开小程序登录 → 修改密码
      │
      ▼
创建更多校区 → 添加教师/学生档案 → 发送邀请链接 → 运营开始
```

### 3.3.2 用户注册与绑定流程

```
用户首次打开小程序
      │
      ▼
微信授权登录 → 自动创建 SysUser（Role=0，无角色用户）
      │
      ▼
绑定手机号
      │
  ┌───┴──────────────────────┐
  │                          │
注册机构信息                 等待邀请链接
（成为机构管理员）            │
  │                          │
  ▼                          ▼
填写机构名称/Logo等         收到机构邀请链接
  │                          │
  ▼                          ▼
创建机构+校区+管理员         点击链接直接跳转小程序页面
  │                          │ (pages/invite/bind?inviteCode=XXX)
  ▼                          │
自动绑定为机构管理员         自动完成绑定（无需手动输入邀请码）
  │                          │
  ▼                          ▼
开始使用                    自动创建 UserOrgBinding
                             角色 变更为 教师或学生或家长
                             （绑定多个机构后所有机构数据同时可见）
                             │
                             ▼
                           开始使用
```

### 4.2.2 课程结算方式配置（变更11，详细展开）

机构管理员创建课程时必须配置以下结算参数：

**结算方式（SettlementType）**：
| 方式 | 编码 | 说明 |
|------|------|------|
| 固定金额 | 0 | 每节课时固定结算金额 |
| 按比例 | 1 | 课程售价÷总课时，向下取整 |

**固定金额模式（SettlementType=0）**：
- 设置 `FixedFeePerLesson`：每节课时固定结算金额（如50元/节）
- 示例：固定50元/节，共10节课 → 教师总收入 500元

**按比例模式（SettlementType=1）**：
- 无需额外配置参数，计算时动态计算
- 计算公式：每节课时费 = Floor(课程售价 ÷ 总课时)
- 示例1：课程售价500元，共10节 → 500÷10=50元/节
- 示例2：课程售价499元，共10节 → Floor(499÷10)=Floor(49.9)=49元/节

**多人班级课时费提成（MaxStudents>1时，变更11）**：

当课程最大人数大于1时（非一对一班级），需额外设置「学生人数课时费提成」：

| 参数 | 字段 | 说明 |
|------|------|------|
| 每增加学生提成金额 | `StudentCountCommission` | decimal(10,2)，多人班级中每增加一个学生，课时费增加的提成金额 |

**多人班级结算计算**：
```
基础课时费 = SettlementType==0 ? FixedFeePerLesson : Floor(CoursePrice / TotalLessons)
实际课时费 = 基础课时费 + (实际选课学生数 - 1) × StudentCountCommission
  注：(实际选课学生数 - 1) 是因为基础课时费已包含1个学生
  如果 (实际选课学生数 - 1) < 0，则按 0 计算
```

**示例**：
- 一对一课程（MaxStudents=1）：基础课时费=50元，无需提成设置，教师每节课收入50元
- 多人课程（MaxStudents=10），固定金额模式，FixedFeePerLesson=30元，StudentCountCommission=5元：
  - 实际选课8人 → 每节课课时费 = 30 + (8-1)×5 = 30+35 = 65元
  - 实际选课3人 → 每节课课时费 = 30 + (3-1)×5 = 30+10 = 40元

# 第九章 评价模块（高级套餐专属）

# 第十章 课程费结算模块

## 10.1 模块概述

课程费结算模块为机构提供教师课时费结算能力。**机构管理员**在发布课程时设置结算方式（变更11），系统每天0点自动结算当天已完成课次的课时费到教师账户。

## 10.2 功能清单

### 10.2.1 结算规则设置（机构管理员，创建课程时，变更11）

| 功能点 | 说明 |
|--------|------|
| 方式A：按固定金额 | 设置每节课时费固定金额（如50元/节） |
| 方式B：按比例结算 | 课程售价 ÷ 总课时数，向下取整，得出每节课时费按比例结算 |
| 多人班级提成 | MaxStudents>1时，设置每增加一个学生的课时费提成金额（StudentCountCommission） |

> ⚠️ **变更11说明**：结算规则直接在Course表中配置（SettlementType、FixedFeePerLesson、StudentCountCommission），不再由教师设置。CourseFeeSettlement表保留用于记录结算明细。

**结算方式举例**：
- **方式A**：课程共10节，每节固定结算50元 → 教师每节课收入50元
- **方式B**：课程售价500元，共10节 → 每节课时费 = 500÷10 = 50元；课程售价499元，共10节 → 499÷10 = 49.9 → 向下取整 = 49元/节
- **多人班级**（方式A，StudentCountCommission=5元）：实际选课8人 → 每节课课时费 = 50 + (8-1)×5 = 85元

### 10.2.2 定时结算任务

| 功能点 | 说明 |
|--------|------|
| 执行时间 | 每天凌晨0点自动执行 |
| 结算范围 | 当天已完成且已过下课时间的课次（状态=已发布，LessonDate=今天，EndTime<当前时间） |
| 结算逻辑 | 根据Course表中的结算规则计算课时费，生成结算记录，更新教师钱包余额 |
| 异常处理 | 结算失败记录日志，支持手动重试 |
| 技术方案 | Hangfire / Quartz 后台 Job |

### 10.2.3 教师钱包（教师，小程序端）

### 12.2.11 课时消耗统计【新增】

根据学生上课动作（签到等），将课程课时分为**已耗课时**和**剩余课时**，并提供多维度汇总：

**核心定义**：

| 概念 | 定义 | 计算方式 |
|------|------|---------|
| **已耗课时** | 学生已完成（签到状态为已到/迟到）的课时数 | 统计 Attendance 表中 ScheduleId 关联课程、Status=1或2 的记录数 |
| **剩余课时** | 学生购买的课程中还未消耗的课时数 | 剩余课时 = 课程总课时(TotalLessons) - 已耗课时 |

**维度一：单学生维度（学生/家长端，小程序）**

| 报表内容 | 说明 |
|----------|------|
| 已耗/剩余课时明细 | 每个学生的每门课程，显示已耗课时数、剩余课时数、消耗进度百分比 |
| 课时消耗时间线 | 每次签到消耗的课时记录（日期、课程、课次、签到状态） |

**维度二：课程维度（机构管理员端，小程序）**

| 报表内容 | 说明 |
|----------|------|
| 课程课时消耗进度 | 每门课程的总课时、整体已消耗课时数、剩余课时数、消耗进度百分比 |
| 课程学生课时明细 | 每门课程下每个学生的已耗/剩余课时列表 |

**维度三：机构维度（机构管理员端，小程序）**

| 报表内容 | 说明 |
|----------|------|
| 机构整体课时消耗 | 全机构所有课程的课时消耗总览（总课时、已消耗、剩余、消耗率） |
| 校区课时消耗对比 | 各校区的课时消耗率对比 |
| 月度课时消耗趋势 | 按月的课时消耗趋势图 |

# 第十三章 数据库设计汇总

> 数据库：MSSQL 2019  
> 连接串：`Server=146.56.242.129;Database=YunKeEdu;User Id=sa;Password=YunKe1478533041;Encrypt=False;TrustServerCertificate=True;`  
> 命名规范：PascalCase，表名无前缀（业务表），系统表用 Sys 前缀

## 13.1 全局约定

1. **主键**：所有表使用 `bigint` 自增主键 `Id`
2. **软删除**：`IsDeleted bit DEFAULT 0`，查询时需过滤 `IsDeleted = 0`
3. **时间审计**：`CreatedAt datetime2 NOT NULL`，`UpdatedAt datetime2 NOT NULL`
4. **多租户隔离**：所有业务表均包含 `TenantId bigint NOT NULL`（= 机构ID）
5. **ORM全局过滤器**：SqlSugar 在查询层自动追加 `WHERE TenantId = @CurrentTenantId`
6. **外键**：逻辑外键（不启用数据库级 FK 约束，通过代码层保证一致性）
7. **TenantId与OrgId关系**：TenantId 即为机构ID，OrgId 字段在部分表中保留以便于显式关联查询
8. **跨机构查询**：教师/学生通过UserOrgBinding绑定多个机构，API查询时根据UserOrgBinding动态构建多租户过滤条件

# 第十四章 API接口汇总

> 接口端：.NET 8 Web API  
> 风格：RESTful  
> 认证：JWT Token（Header: `Authorization: Bearer {token}`）  
> 数据格式：JSON  
> 统一响应结构：`{ code: 0, message: "success", data: T }`

## 14.1 全局约定

1. **分页请求**：`GET /api/xxx/page?page=1&pageSize=20&keyword=xxx&status=0`
2. **分页响应**：`{ code: 0, data: { items: [], total: 100, page: 1, pageSize: 20 } }`
3. **错误码**：0=成功，400=参数错误，401=未授权，403=无权限/套餐不支持，404=不存在，500=服务器错误
4. **多租户过滤**：JwtMiddleware 解析 Token 中的 TenantId 注入 HttpContext，SqlSugar 全局过滤器自动追加。教师/学生跨机构查询时根据UserOrgBinding动态构建多租户过滤条件
5. **套餐权限校验**：API层统一校验当前机构套餐是否包含所需功能（通过 FeatureCode + MinPackageLevel）
6. **Ultra套餐专属校验**：评价相关API需校验机构套餐等级是否≥2（Ultra），否则返回"当前套餐不支持评价功能"
