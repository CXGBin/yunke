# 0. 总览 — 云科智教课程管理平台

## 1. 项目概述

**云科智教**是一套面向教育培训机构的课程全生命周期管理平台，覆盖课程发布、选课、排课、签到、评价、数据分析等核心业务。系统包含：

- **小程序端**（学生/家长）：课程浏览、选课退课、课表查看、签到打卡、课程评价
- **PC管理端**（教师/机构管理员/平台管理员）：课程管理、排课调度、签到管理、评价管理、数据报表、系统配置

## 2. 角色体系

### 2.1 角色层级树形结构

```
平台方（SaaS运营方）  ← 最高层级
  │
  └── 教育机构方（租户）
        │
        ├── 校区A（物理分支机构）
        │     ├── 教师（归属机构+校区）
        │     ├── 学生（归属机构+校区）
        │     └── 家长 ──关联──→ 学生
        ├── 校区B
        │     ├── 教师
        │     ├── 学生
        │     └── 家长 ──关联──→ 学生
        └── ...
```

### 2.2 角色定义与权限边界

| 角色 | 端 | 所属层级 | 核心职责 |
|------|-----|---------|---------|
| **平台管理员** | PC端 | 平台方 | 管理所有机构/校区、全局数据监控、平台配置、系统维护 |
| **机构管理员** | PC端 | 机构方 | 管理本机构所有校区、教师、课程、排课、审核评价、查看报表 |
| **教师** | PC端 + 小程序 | 机构方/校区 | 发布课程、查看排课、课堂签到、查看评价、查看教学数据 |
| **学生** | 小程序 | 机构方/校区 | 选课、查看课表、签到、课程评价、查看成绩/报告 |
| **家长** | 小程序 | 学生关联方 | 关注孩子课程、查看出勤、接收通知、代缴费用（预留） |

### 2.3 权限边界规则

| 维度 | 平台管理员 | 机构管理员 | 教师 | 学生/家长 |
|------|:---------:|:---------:|:----:|:---------:|
| 数据可见范围 | 全平台 | 本机构所有校区 | 本校区 | 本校区（自己） |
| 管理机构/校区 | ✅ 全平台 | ✅ 本机构内 | ❌ | ❌ |
| 管理教师 | ✅ | ✅ 本机构 | ❌ | ❌ |
| 管理学生 | ✅ | ✅ 本机构 | ❌ | ❌ |
| 课程管理 | ✅ 全平台 | ✅ 本机构 | ✅ 自己授课 | ❌ |
| 查看报表 | 全平台汇总 | 本机构汇总 | 自己教学数据 | 个人/孩子数据 |
| 平台配置 | ✅ | ❌ | ❌ | ❌ |

### 2.4 机构与校区关系

- **机构（Organization）**：最高租户单元，一个机构就是一个独立的教育实体（如"阳光少儿英语"）
- **校区（Campus）**：机构下的物理分支，用于排课、签到、教室管理等场景（如"阳光少儿英语-海淀校区"）
- 一个机构包含多个校区（至少1个默认校区）
- 所有业务数据（课程、排课、教室、签到）挂载到**校区**维度
- 教师和学生归属到具体校区
- 数据隔离：机构管理员可查看本机构所有校区数据；教师/学生只能看到所属校区数据

### 2.5 教师归属关系

- 教师必须归属一个机构和一个主校区（CampusId）
- 支持教师跨校区授课（通过排课模块指定不同校区的教室）
- 教师的身份信息在机构层面统一管理

### 2.6 学生与家长关联关系

- 家长有**独立账号**，通过微信登录后绑定手机号
- 一个家长可关联**多个孩子**（如二胎/多孩家庭）
- 一个孩子可关联**多个家长**（如父母双方）
- 家长通过"关联学生"功能绑定孩子（需验证，如输入孩子学号或扫码确认）
- 家长可查看所有关联孩子的课程、出勤、评价等信息
- 学生/家长均有独立登录入口，角色标识区分

### 2.7 各角色注册/开通流程

```
平台管理员创建/开通机构账号
      │
      ▼
机构管理员登录 → 创建校区（至少1个默认校区）
      │
      ├──→ 添加教师（指定归属校区）
      │       │
      │       ▼
      │     教师登录PC端/小程序（机构管理员分配账号或教师自主注册+审核）
      │
      └──→ 学生/家长自行注册小程序
              │
              ▼
           微信登录 → 绑定手机号 → 选择机构/校区 → 提交
              │
              ▼
           机构管理员审核通过（可选）
              │
              ▼
           学生/家长使用
              │
              ▼
           家长通过"关联学生"功能绑定孩子
```

PC端采用多页签（Tabs）布局：
- 左侧固定菜单栏

- 每个页签独立路由和状态
- 页签状态持久化（刷新不丢失）

## 4. 全局设计

### 4.1 多租户架构（共享库 + TenantId）

> **核心决策**：采用共享数据库 + TenantId 字段方案（不使用数据库隔离），方便平台方跨租户汇总统计数据。

**架构说明**：
- 所有业务表均包含 `TenantId`（即机构ID）字段，数据通过 TenantId 隔离
- 一个机构（租户）对应一个 TenantId，机构下的校区通过 CampusId 进一步细分
- 平台管理员可跨 TenantId 查询，实现全平台汇总统计（课程数、学员数、营收等）
- 教师和学生归属到具体校区（CampusId），以校区为最小业务操作单元

**与财务管理系统（单租户）的差异**：
- 财务系统为单租户架构，无租户隔离需求
- 云科智教从架构层面原生支持多租户，所有业务层、数据层均需处理租户上下文

### 4.2 SqlSugar 多租户全局过滤器

在 ORM 层（SqlSugar）实现租户数据的自动过滤，避免业务代码手动处理：

```
// JwtMiddleware 解析 Token → 注入 CurrentTenantId 到 HttpContext
// SqlSugar 拦截器自动追加 WHERE TenantId = @CurrentTenantId

// 配置方式（Program.cs / Startup）：
sqlSugar.AddFilterTable(new TableFilterItem<object>(t =>
    t.TenantId == CurrentTenantId));

// 平台管理员查询时，移除过滤器实现跨租户查询：
sqlSugar.RemoveFilterTable(typeof(Course));
```

**关键规则**：
1. 所有业务实体基类包含 `TenantId` 字段
2. 中间件从 JWT Token 提取 TenantId 注入请求上下文
3. SqlSugar 全局过滤器自动追加 `WHERE TenantId = @val`
4. 平台管理员跨租户查询时，通过标记显式移除过滤器
5. 创建/更新操作自动填充 TenantId，无需业务层手动赋值
6. 平台管理员（TenantId = NULL）不受过滤器影响

### 4.3 多校区隔离

- 所有业务数据通过 `TenantId` + `CampusId` 字段隔离
- 机构管理员可查看本租户所有校区数据（过滤器仅按 TenantId）
- 平台管理员可跨租户查看（移除过滤器）
- 教师/学生/家长自动归属注册时选择的机构和校区
- 排课、教室、签到等场景以校区为最小管理单元

### 4.4 主题切换（小程序端）

- 支持多套主题样式（如：蓝色科技风、绿色清新风、紫色优雅风）
- 主题由机构管理员配置，或学生自行切换
- 主题配置存储在数据库，包含主色、辅色、按钮色、背景色等

### 4.5 认证方案

- 小程序端：微信登录 → 绑定手机号 → JWT Token
- PC端：账号密码登录 → JWT Token
- Token有效期：7天，支持刷新

### 4.6 通知机制

- 小程序订阅消息（上课提醒、签到提醒、评价提醒）
- PC端站内消息
- 预留短信/公众号通知

> ⚠️ **待确认**：是否需要消息推送功能？还是仅站内消息即可？
